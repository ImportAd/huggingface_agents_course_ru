## Когда стоит использовать агентный фреймворк [[when-to-use-an-agentic-framework]]

Агентный фреймворк **нужен не каждому приложению на основе LLM**. Такие фреймворки позволяют гибко выстраивать рабочий процесс для эффективного решения конкретной задачи, но необходимы не всегда.

Иногда для выполнения запросов пользователей **достаточно заранее заданного рабочего процесса**, и особой потребности в агентном фреймворке нет. Если агент устроен просто — например, как цепочка промптов, — может хватить обычного кода. Преимущество такого подхода в том, что разработчик **полностью контролирует систему и понимает её устройство без дополнительных абстракций**.

Однако по мере усложнения рабочего процесса — например, когда LLM получает возможность вызывать функции или в системе появляются несколько агентов — эти абстракции становятся полезными.

Уже сейчас можно выделить несколько необходимых возможностей:

* *LLM*, на которой работает система.
* *Список инструментов*, доступных агенту.
* *Парсер* для извлечения вызовов инструментов из вывода LLM.
* *Системный промпт*, согласованный с парсером.
* *Система памяти*.
* *Журналирование ошибок и механизмы повторных попыток*, позволяющие справляться с ошибками LLM.

Мы рассмотрим, как эти задачи решаются в разных фреймворках: `smolagents`, `LlamaIndex` и `LangGraph`.
