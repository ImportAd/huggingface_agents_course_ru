# Мысль: внутреннее рассуждение и подход ReAct [[thought-internal-reasoning-and-the-react-approach]]

> [!TIP]
> В этом уроке мы заглянем внутрь процесса работы агента: как он анализирует сведения, разбивает задачу на шаги и решает, что делать дальше. Познакомимся и с ReAct — подходом, который чередует рассуждение и действия.

**Мысли** в схеме работы агента обозначают его внутренние процессы рассуждения и планирования. Языковая модель анализирует сведения в промпте, сопоставляет их с наблюдениями и выбирает дальнейший шаг. Так агент может разделить сложную задачу на части, учесть предыдущие результаты и изменить план по мере поступления новой информации.

При этом слово «мысль» описывает учебную модель поведения, а не гарантирует, что все внутренние рассуждения LLM доступны приложению или достоверно отражены в тексте ответа. Для проверки действий смотрите на вызовы инструментов и наблюдения.

## 🧠 Примеры распространённых типов мыслей [[-examples-of-common-thought-types]]

| Тип | Пример |
| :-- | :-- |
| Планирование | «Разобью задачу на три шага: собрать данные, проанализировать тенденции, подготовить отчёт». |
| Анализ | «По сообщению об ошибке похоже, что неверно заданы параметры подключения к базе данных». |
| Принятие решения | «С учётом бюджета пользователя предложу вариант среднего уровня». |
| Поиск решения | «Сначала измерю производительность кода, чтобы найти узкое место». |
| Использование памяти | «Пользователь раньше сказал, что предпочитает Python, поэтому приведу примеры на Python». |
| Самопроверка | «Прошлый способ не сработал, попробую другой». |
| Постановка цели | «Сначала определю критерии успешного выполнения задачи». |
| Приоритизация | «Уязвимость безопасности нужно исправить до добавления новых функций». |

> **Примечание:** при вызове функций модель может сразу выбрать инструмент, не выдавая отдельный текст с рассуждением. Подробнее об этом — в уроке о [действиях](actions).

## 🔗 Цепочка рассуждений (Chain-of-Thought, CoT) [[-chain-of-thought-cot]]

**Chain-of-Thought** — способ побудить модель последовательно разобрать задачу перед ответом. Простая подсказка может звучать так: «Думай шаг за шагом». Это помогает с логическими и математическими задачами **без обращения к внешним инструментам**.

### ✅ Пример CoT [[-example-cot]]

```text
Вопрос: Сколько составит 15% от 200?
Рассуждение: 10% от 200 — это 20, а 5% — это 10. Значит, 15% — это 30.
Ответ: 30.
```

Записанные шаги могут помочь читателю понять ответ, но сами по себе не доказывают его правильность. Для точного расчёта агент может воспользоваться проверенным инструментом.

## ⚙️ ReAct: рассуждение и действие [[️-react-reasoning--acting]]

Подход **ReAct** сочетает рассуждение (*Reasoning*) и действие (*Acting*). В учебной схеме агент чередует выбор следующего шага с вызовом инструмента и получением результата:

- **Мысль:** что нужно узнать или сделать дальше.
- **Действие:** использование инструмента.
- **Наблюдение:** результат действия, на который можно опереться в следующем шаге.

### 🔄 Пример ReAct [[-example-react]]

```text
Мысль: Чтобы ответить, нужны текущие сведения о погоде в Париже.
Действие: Search["погода в Париже"]
Наблюдение: 18 °C, облачно.
Мысль: Теперь у меня есть данные для ответа.
Действие: Finish["Сейчас в Париже 18 °C и облачно."]
```

## 🔁 Сравнение ReAct и CoT [[-comparison-react-vs-cot]]

| Свойство | Chain-of-Thought | ReAct |
| :-- | :-- | :-- |
| Последовательные шаги | Да | Да |
| Внешние инструменты | Нет | Да: действия и наблюдения |
| Типичные задачи | Логика и внутренние вычисления | Поиск сведений и многошаговые задачи |

> [!TIP]
> Некоторые модели, например DeepSeek R1 и OpenAI o1, обучались разделять этапы рассуждения и ответа. Это свойство модели, тогда как CoT и ReAct описывают подходы к построению промптов и рабочего цикла. Не полагайтесь на текст рассуждения как на замену проверке ответа.
